What is Image-to-Video Generation?

Image-to-Video (I2V) is the task of generating a temporally coherent video clip from a single still image, optionally guided by a text prompt. Given one frame, the model must invent plausible motion — camera dynamics, object movement, lighting changes — while remaining faithful to the input image.

Intuition: hand the model a photograph of a waterfall and ask it to bring it to life. It must decide how the water flows, how mist drifts, how light scatters — all inferred from one static frame.

Why It's Difficult

  • Temporal consistency — objects must remain coherent across frames. A face cannot subtly shift shape between frame 5 and frame 6.
  • Causal structure — the model must understand that frame N depends only on frames 0 through N−1, not frames yet to come.
  • Scale — a 4-second 24fps video is 96 frames. Processing them jointly in pixel space is computationally infeasible without compression.
  • Conditioning fidelity — the generated video must look like the input image, not just be vaguely similar to it.

The Modern Recipe

State-of-the-art I2V models (WAN, CogVideoX, Open-Sora) all converge on the same architectural pattern:

Video VAE
Compress video from pixels into a compact 3D latent space. Makes diffusion ~64× cheaper to run.
Diffusion Transformer
A transformer that denoises latent video, attending across space and time simultaneously.
Flow Matching
Training objective that learns straight-line paths from noise to data. Faster and simpler than DDPM.
Conditioning
The input image and text are encoded and injected via cross-attention at every denoising step.

What This Series Builds

We implement each component from scratch in PyTorch. By the end you will have a structurally faithful I2V pipeline:

Image + Text→VAE Encode→Noisy Latent→DiT Denoise→VAE Decode→Video

If you have worked with LLMs or basic diffusion models before, many ideas here will feel familiar. Let's begin.

One of the core building blocks of modern video generation architectures is CausalConv3d. In Transformers we use a causal attention mask so that token t can only see previous tokens. Video generation follows the exact same principle — except instead of generating words, we generate frames:

frame₀ → frame₁ → frame₂ → ...

Conceptually identical to autoregressive text generation:

word₀ → word₁ → word₂ → ...

Why Causal Conv3D?

In video models, tensors are shaped as (T × H × W) — time, height, width. For example, 8 × 32 × 32 means 8 frames of 32×32 resolution. A standard Conv3D with kernel 3 × 3 × 3 is not causal — while processing frame t, the convolution may look at [t-1, t, t+1].

Problem: during autoregressive generation, frame t+1 belongs to the future. The model should never access future frames while generating the current one.

CausalConv3D fixes this by restricting the temporal receptive field to past and present only:

[t-2, t-1, t]

Temporal Padding

At the beginning of the sequence (t = 0), there are no previous frames. We pad the temporal dimension on the left side only:

[pad, pad, t0, t1, t2, ...]
Key idea: temporal padding is applied only on the left side so future frames are never exposed to the convolution kernel.

Implementation

vae/conv.py 
import torch
import torch.nn as nn
import torch.nn.functional as F


class CausalConv3d(nn.Module):
    """
    Conv3d that is causal in the time dimension.
    Spatial dims (H, W) use standard symmetric padding.
    Time dim uses left-only padding so the kernel never sees future frames.
    """

    def __init__(
        self,
        in_channels: int,
        out_channels: int,
        kernel_size: int | tuple,
        stride: int | tuple = 1,
        dilation: int | tuple = 1,
        bias: bool = True,
    ):
        super().__init__()

        if isinstance(kernel_size, int):
            kernel_size = (kernel_size, kernel_size, kernel_size)
        if isinstance(stride, int):
            stride = (stride, stride, stride)
        if isinstance(dilation, int):
            dilation = (dilation, dilation, dilation)

        kt, kh, kw = kernel_size
        dt, dh, dw = dilation

        self.time_pad = (kt - 1) * dt      # left-only temporal padding
        pad_h = (kh - 1) * dh // 2        # symmetric spatial padding
        pad_w = (kw - 1) * dw // 2

        self.conv = nn.Conv3d(
            in_channels, out_channels,
            kernel_size=kernel_size,
            stride=stride,
            dilation=dilation,
            padding=(0, pad_h, pad_w),
            bias=bias,
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # x: (B, C, T, H, W)
        if self.time_pad > 0:
            x = F.pad(x, (0, 0, 0, 0, self.time_pad, 0))
        return self.conv(x)


class CausalConv3d_1x1(nn.Module):
    """Pointwise (1×1×1) conv — no padding needed."""

    def __init__(self, in_channels: int, out_channels: int, bias: bool = True):
        super().__init__()
        self.conv = nn.Conv3d(in_channels, out_channels, kernel_size=1, bias=bias)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.conv(x)

Dilation

A kernel of size 3 normally samples adjacent positions:

[n-1, n, n+1]

With dilation=2, gaps are inserted between samples:

[n-2, n, n+2]
Effect: dilation increases the receptive field without increasing kernel size or parameter count. Essential for capturing motion patterns that span multiple frames.
Small dilation
Focuses on local motion and nearby frame relationships.
Large dilation
Captures longer-range temporal dependencies across distant frames.

Why the Padding Formula?

pad_h    = (kh - 1) * dh // 2   # symmetric, keeps H dimension
pad_w    = (kw - 1) * dw // 2   # symmetric, keeps W dimension
time_pad = (kt - 1) * dt        # left-only, causal

Consider Input: 8×32×32, kernel 3×3×3, dilation 2×2×2. The effective kernel size is:

effective = (kernel - 1) × dilation + 1
          = (3 - 1) × 2 + 1 = 5

Without padding, output dimensions would collapse:

T = (8  - 5) + 1 = 4
H = (32 - 5) + 1 = 28
W = (32 - 5) + 1 = 28    → 4×28×28

With our padding (time_pad=4, pad_h=pad_w=2), the padded input becomes 12×36×36 and output stays close to 8×32×32. Stacking layers without this would collapse the video to nothing.

Spatial vs. Temporal Padding

DimensionPaddingReason
TimeLeft-onlyFuture frames must never be visible
HeightSymmetricNo notion of "future" pixels spatially
WidthSymmetricNo notion of "future" pixels spatially

Key Takeaways

  • CausalConv3D prevents future frame leakage, analogous to causal attention in Transformers
  • Temporal padding is applied left-only; spatial padding is symmetric
  • Dilation expands the receptive field without adding parameters
  • Correct padding preserves output dimensions through deep networks

Spatial reasoning
Understanding objects, textures, edges, shapes, and appearance inside each frame.
Temporal reasoning
Understanding motion, continuity, transitions, and how the scene evolves over time.

Data Flow

x → GroupNorm → SiLU → CausalConv3D(3×3×3)
  → GroupNorm → SiLU → CausalConv3D(3×3×3)

Spatial Understanding

Spatially, CausalConv3D behaves like a standard convolution. Early layers learn low-level patterns — edges, corners, gradients. Deeper layers learn shapes, objects, and scene layouts. This is the same as CNNs for images; the difference is the model also reasons across time.

Temporal Understanding

The temporal kernel (size 3 or 5) analyzes several neighboring frames together, learning the underlying motion continuity of the scene. A single block looking at 3 frames may seem limited, but stacked blocks compound:

Layer 1 sees frames [t-1, t, t+1]
Layer 2 sees three "Layer 1 summaries"
Layer 3 sees even broader summaries
...
Eventually: effective range of 15–20 frames
Example: if a person is halfway through a blink in frame 1 and frame 2, the model learns that frame 3 should continue the motion naturally rather than reset the eye position.

Why Skip Connections?

The block is called residual because of the skip connection:

output = F(x) + x

This creates a direct path for information and gradients to bypass the transformation. The benefits are well-established: vanishing gradients are reduced, low-level information is preserved, and very deep networks remain trainable.

Pre-Norm vs. Post-Norm

Modern architectures prefer Pre-Norm — normalization before the transformation, not after the residual addition.

Post-Norm (older style):

x → Transform(x) → + skip(x) → Norm → output

Pre-Norm (modern style):

x → Norm → Transform(x) → + skip(x) → output

In Pre-Norm, the skip path is clean — gradients flow straight through without passing through a normalization layer. This leads to better optimization stability in deep networks.

Why GroupNorm?

BatchNorm — not suitable
Depends on batch statistics. Video models run with tiny batch sizes (high memory), making batch stats noisy and training unstable.
LayerNorm — decent but
Normalizes all channels equally. Works great for transformers but may not preserve spatial/channel structure in CNN-style blocks.

GroupNorm divides channels into groups and normalizes each group independently. It is completely independent of batch size — stable even at batch size 1 — which is why it dominates in diffusion models, video VAEs, and other memory-intensive vision systems.

Implementation

vae/resblock.py 
class ResBlock3D(nn.Module):
    """
    3D residual block for the VAE encoder/decoder.

    Structure:
        x → Norm → SiLU → Conv3D(3×3×3)
          → Norm → SiLU → Conv3D(3×3×3)
          → + skip(x)

    Skip uses a 1×1×1 conv if in/out channels differ, else identity.
    """

    def __init__(self, in_channels: int, out_channels: int, num_groups: int = 32):
        super().__init__()

        self.norm1 = nn.GroupNorm(num_groups, in_channels)
        self.conv1 = CausalConv3d(in_channels, out_channels, kernel_size=3)

        self.norm2 = nn.GroupNorm(num_groups, out_channels)
        self.conv2 = CausalConv3d(out_channels, out_channels, kernel_size=3)

        self.act  = nn.SiLU()
        self.skip = (
            CausalConv3d_1x1(in_channels, out_channels)
            if in_channels != out_channels
            else nn.Identity()
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        residual = self.skip(x)

        x = self.act(self.norm1(x))
        x = self.conv1(x)
        x = self.act(self.norm2(x))
        x = self.conv2(x)

        return x + residual

Key Takeaways

  • ResBlock3D processes spatial and temporal information simultaneously
  • Stacking blocks compounds the temporal receptive field significantly
  • Skip connections stabilize gradient flow in deep networks
  • Pre-Norm produces cleaner gradient paths than Post-Norm
  • GroupNorm is the right choice when batch sizes are small

The Positional Encoding Problem

Transformers process tokens as an unordered set — they have no inherent sense of which token comes before another. For video, position is three-dimensional: height, width, and time. We need to inform the model of each token's location in all three axes.

Classic absolute positional embeddings (added to token embeddings) work but generalize poorly to video lengths not seen during training.

RoPE: Rotating Queries and Keys

Rotary Positional Embeddings (RoPE) encode position by rotating the query and key vectors before computing attention — rather than adding a fixed offset to the tokens. The key property: the dot product q·k depends only on the relative position of the two tokens, not their absolute positions.

Why this matters: relative position encoding generalizes naturally. A token three steps away always has the same relationship, regardless of where in the video it appears — enabling better length generalization.

Extending RoPE to 3D

We split the embedding dimensions across three axes and apply independent rotations per axis:

    dt, dh, dw = dim // 4, dim // 4, dim // 2
    freq_t = sincos_freqs(T, dt)  # (T, dt) — temporal axis
    freq_h = sincos_freqs(H, dh)  # (H, dh) — vertical axis
    freq_w = sincos_freqs(W, dw)  # (W, dw) — horizontal axis
    return freq_t, freq_h, freq_w

def apply_rope(q, k, freqs):
    return rotate_half(q, freqs), rotate_half(k, freqs)

Frequency Bands

Low frequencies
Distinguish tokens far apart — are we in the first or second half of the video?
High frequencies
Distinguish adjacent tokens — is this pixel one step left or right of that one?

The temporal axis uses a lower base frequency (videos are shorter in frame count than wide in pixels). Spatial axes use higher base frequencies for fine-grained position. Crucially, RoPE is applied inside the attention computation — rotating queries and keys, not modifying the tokens themselves.

Attention in One Line

Attention lets every token ask a question (query), listen to every other token's answer (key-value pair), and aggregate information weighted by relevance:

Attention(Q, K, V) = softmax( QKᵀ / √d ) · V

Self-Attention over Video Tokens

In a video DiT, the 3D latent (T×H×W) is flattened into a 1D sequence of tokens, then self-attention runs across all of them. Every frame attends to every other frame, and every spatial position attends to every other position — enabling global temporal consistency.

Cost: full 3D self-attention is O(N²) where N = T×H×W. For a 16-frame 64×64 latent, N = 65,536. Flash Attention avoids materializing the full N×N matrix, making this tractable.

Cross-Attention for Conditioning

The DiT Architecture

The Diffusion Transformer (DiT) is a standard transformer stack — self-attention, cross-attention, feed-forward MLP — with one key modification: the normalization layers are adaptive. Their scale and shift parameters are predicted from the current diffusion timestep, not learned as static parameters.

Why Adaptive Normalization?

The model sees different noise levels at each timestep. A latent that is 90% noise requires very different processing from one that is 10% noise. Conditioning on the timestep only via an added token embedding is too weak — we need the timestep to modulate the entire computation at every layer.

adaLN: instead of fixed learnable γ and β in LayerNorm, we predict them from the timestep embedding. Every DiT layer gets its own scale and shift, conditioned on the current noise level.

adaLN-Zero Initialization

The output projection of each adaptive block is initialized to zero. At initialization the block is an identity function, giving the model a well-behaved starting point. It gradually learns to use the conditioning signal during training.

dit_block.py 
class AdaLN(nn.Module):
    def __init__(self, dim, cond_dim):
        super().__init__()
        self.norm = nn.LayerNorm(dim, elementwise_affine=False)
        self.mlp  = nn.Sequential(nn.SiLU(), nn.Linear(cond_dim, 2 * dim))

    def forward(self, x, c):
        shift, scale = self.mlp(c).chunk(2, dim=-1)
        return self.norm(x) * (1 + scale) + shift


class DiTBlock(nn.Module):
    def __init__(self, dim, heads, ctx_dim):
        super().__init__()
        self.n1, self.attn  = AdaLN(dim, ctx_dim), SelfAttention(dim, heads)
        self.n2, self.cross = AdaLN(dim, ctx_dim), CrossAttention(dim, ctx_dim)
        self.n3, self.ff    = AdaLN(dim, ctx_dim), FeedForward(dim)

    def forward(self, x, c, ctx):
        x = x + self.attn(self.n1(x, c))
        x = x + self.cross(self.n2(x, c), ctx)
        x = x + self.ff(self.n3(x, c))
        return x

Timestep Embedding

Sinusoidal Projection
Maps scalar t to a 256-dim vector using sine/cosine at different frequencies. Gives smooth interpolation across timesteps.
MLP Refinement
Two linear layers with SiLU activation map sinusoidal features to the model's hidden dimension d.

The Problem with DDPM

Denoising Diffusion Probabilistic Models add noise via a fixed Markov chain and learn to reverse it. They work well, but require carefully tuned noise schedules and hundreds of inference steps.

Flow Matching

Flow matching learns a vector field that moves samples from noise to data. The simplest version uses straight-line paths: the flow from noise x₀ ~ N(0,I) to data x₁ is the straight line between them.

Rectified Flow: at any t ∈ [0,1], the interpolated sample is xₜ = (1−t)·x₀ + t·x₁. The target velocity is the constant v = x₁ − x₀. The model learns to predict this velocity — much simpler than DDPM's time-varying noise prediction.

Training

flow_matching.py 
def flow_matching_loss(model, x1, cond):
    B  = x1.shape[0]
    t  = torch.rand(B, device=x1.device)        # uniform t ∈ [0, 1]
    x0 = torch.randn_like(x1)
    t_ = t[:, None, None, None, None]
    xt = (1 - t_) * x0 + t_ * x1              # straight-line interpolation

    v_pred   = model(xt, t, cond)
    v_target = x1 - x0                          # constant target velocity
    return F.mse_loss(v_pred, v_target)

Inference: Euler Integration

Start from pure noise and integrate the learned velocity forward:

x = torch.randn(B, C, T, H, W)
for t in torch.linspace(0, 1, steps=20):
    v = model(x, t, cond)
    x = x + v / steps

Because paths are straight lines, good samples emerge in 10–20 steps — far fewer than DDPM's typical 1000. This is why WAN, CogVideoX, and most recent video models have adopted flow matching.

DDPM
Learns curved denoising paths. Requires ~1000 steps at inference. Sensitive to noise schedule choice.
Flow Matching
Learns straight-line paths. 10–20 inference steps. Simple MSE objective. Scales well to video.

Two Conditioning Signals

An I2V model is guided by two sources: a reference image (the first frame the video must start from) and an optional text prompt (describing desired motion or scene). Each must be encoded into a form the DiT can consume via cross-attention.

Text Encoding

Text is encoded with a frozen T5 or CLIP encoder. The encoder outputs one dense embedding per token — these become the keys and values in cross-attention layers:

encoders.py 
from transformers import T5EncoderModel, T5Tokenizer

tokenizer = T5Tokenizer.from_pretrained("t5-base")
encoder   = T5EncoderModel.from_pretrained("t5-base")

def encode_text(prompt: str) -> torch.Tensor:
    tokens = tokenizer(prompt, return_tensors="pt", padding=True)
    with torch.no_grad():
        out = encoder(**tokens)
    return out.last_hidden_state  # (B, seq_len, d)

Image Conditioning

Two complementary strategies are used together in most production I2V models:

Latent Concatenation
Encode the reference image with the VAE encoder. Concatenate it with the noisy video latent along the channel dimension. The DiT sees both at every step, preserving pixel-level fidelity.
CLIP Image Embedding
Encode the image with CLIP's visual encoder for semantic representation. Added to the text tokens as additional cross-attention context.

Classifier-Free Guidance

To strengthen conditioning, we train with CFG: with ~15% probability, drop all conditioning and train unconditionally. At inference, combine both predictions:

v_guided = v_uncond + scale × (v_cond - v_uncond)

Scale 1.0 is unconditional; 7.0 is strongly conditional. This lets you dial adherence to the image and text without retraining.

Key insight: CFG doesn't need a separate classifier. The same model produces both conditional and unconditional predictions — the unconditional pass simply nullifies the conditioning tokens.
